PW-1x Build Sheet

Projectile William v1 — a local agent and coding rig on EPYC Rome, doubling as a host for websites and dev environments. What's bought, which models actually fit, and what to upgrade when.

Settled

128GB — ordered

Every US open-weight model worth running fits inside 128GB. Doubling to 256GB unlocks no new model — it buys context headroom on one option that isn't worth running anyway.

All eight slots filled, all eight sticks the same part number. The board is 1 DIMM per channel, so four sticks is four channels and half the bandwidth — which is the entire reason for this platform.

Kingston’s compatibility database lists 16GB DDR4-3200 2Rx8 RDIMM for this board and specifies modules be installed in groups of eight, max 512GB with RDIMMs. The spec is vendor-confirmed, not inferred.

Hard rejects: anything slower than PC4-25600 (it downclocks the whole system, and 2933 currently costs more per GB than 3200 anyway); UDIMM; single-rank 1Rx4 or 1Rx8.

On arrival — assemble, then test the memory

Assembly comes first. memtest86+ needs the processor, cooler, supply and board mounted and POSTing, so it cannot run before the machine is built — earlier revisions of this sheet implied otherwise. Then run memtest86+ on all eight sticks together, full passes overnight, and again one stick at a time if anything errors. Do it inside the 30-day return window, not after.

This is what the window is actually for. A bad stick found in week one is a defective return — the vendor pays shipping and the restocking fee never comes up. The same stick failing in month four is a warranty claim: slower, and on a 1DPC board it means finding a matched replacement or replacing all eight.

Close out the three quote threads with a one-line "covered on 128GB, thanks." Topmemory especially — fleet pulls are where a GPU and any CPU swap will come from.

The board has no SATA ports

Storage is two M.2 slots plus two OCuLink and two miniSAS HD connectors. Any SATA drive needs a breakout cable — which is why the G-DRIVE stays in its enclosure on USB rather than being shucked.

Two tiers. Active models on the NVMe, where a 63GB load takes ~12 seconds. Library on the G-DRIVE, where the same copy takes ~7½ minutes — fine for something fetched occasionally, unusable as the live path. Portable USB HDDs aren’t rated for continuous duty, so let it idle between pulls.

The pairing — there is no card to pair with

Correction, Sept 2026. Earlier revisions of this sheet built a plan around a 16GB 4060 Ti. The card is 8GB, and it stays in the desktop rather than moving into PW-1x. Both halves of that assumption are now gone.

What it means for the small model: gpt-oss-20b’s 12.1GB of weights do not fit 8GB of VRAM at all, so on the desktop it runs half on the card and half on the processor, measured at 39 tok/s. It is still useful for volume work; it is not the fast resident tier this sheet described.

What it means for PW-1x: the machine starts with no GPU, every weight in RAM, and prompt processing done by the processor. A card bought later wants 24GB or more to hold the small model and the large one’s attention layers together — which is the same conclusion this sheet reached, for a different reason.

The runnable set is two models, not four. Nemotron needs a fork; Maverick is a skip. That leaves gpt-oss-120b at 63GB and Llama 4 Scout at 62–65GB — both on stock llama.cpp, both comfortably inside 128GB with ~60GB left for KV cache. That headroom is the argument for 128GB, and the reason 256GB adds nothing.

Runtime

How the split works

llama.cpp with --n-cpu-moe is the mechanism that makes this build viable once a GPU exists: always-active weights on the card, routed experts in system RAM. PW-1x has no card yet, so the machine starts CPU-only with everything in RAM and these flags idle. Keep this section for the day one is fitted.

llama-server -m gpt-oss-120b-Q8_0.gguf \
  --n-cpu-moe 40 \
  -ngl 999 \
  -b 4096 -ub 4096 \
  -c 32768

--n-cpu-moe N pushes the top N expert layers to CPU, counting down from the highest-numbered layer, overriding the -ngl 999 that put everything on the GPU first. Start high, tune downward until VRAM is nearly full — every expert layer you claw back onto the card is free speed.

Batch size is the setting people leave on defaults and then wonder why prefill crawls. -b 4096 -ub 4096 is the difference between usable and painful.

ik_llama.cpp is the fork to try if you want to tune harder; it adds graph-split modes that help once a second GPU is in the picture.

Second role

Also hosts websites and dev environments

Different resources than inference wants — network and disk rather than memory bandwidth — so the two coexist without meaningfully slowing each other.

Two things to get right

Co-location is the real risk, not performance. A public site sharing a host with your dev environments and the model stack means a compromise lands next to everything. Run anything internet-facing in rootless Podman and treat the host as exposed.

Builds are the one workload that fights inference. A big parallel compile takes every core and hits memory hard, and that's when token latency spikes. Cap it — -j16, not -j32.

The CPU is 32 cores but 64 logical CPUs. Linux enumerates 0–63. Pinning inference to 0-11 alone leaves 32–43 — the SMT siblings of those same physical cores — open for containers, so the isolation does nothing. Pin each core with its sibling, and confirm the pairing with lscpu -e=CPU,CORE first: enumeration order varies by kernel and BIOS. Memory caps must sum below 128GB or the OOM killer picks a winner, and it will usually pick the 63GB process.

Debian or Ubuntu on bare metal — no hypervisor, since GPU passthrough to a guest adds real complexity and buys nothing. Podman for containers (rootless, no daemon), Caddy as reverse proxy for automatic Let's Encrypt certs, Tailscale free tier for remote access without opening ports.

Put /var/lib/containers on its own partition. Image sprawl accumulates faster than you expect, and a runaway pull must not be able to fill the disk out from under the model files.

Constraints

Where this hurts

  • Prefill on long context, with no GPU at all. PW-1x runs CPU-only, so prompt processing has nothing behind it. The daily annoyance once an agent is pointed at a large repo, and the first thing worth fixing.
  • ~140 GB/s is a hard wall. Dell measured 270–300 GB/s dual-socket STREAM Triad on the 7452, so roughly 135–150 per socket. No configuration gets past it, and it’s inherent to SP3 — Genoa’s ~460 GB/s needs a different socket, board, and memory.
  • The 7452 is a 4-CCD part (inferred: 128MB L3 at 32MB per Rome CCD — no vendor doc states it outright). It is not one of the bandwidth-crippled SKUs; those are the 2-CCD parts — 7282, 7272, 7252, 7232P — which lose roughly half their bandwidth to fabric limits. Dell measured the 7452 in the same STREAM band as the 8-CCD 7702, so the conclusion rests on measurement rather than on the CCD count.
  • Rome is excluded from ZenDNN. AMD's 2–4.5× llama.cpp prompt-processing speedup covers Milan, Genoa and Turin, not Zen 2. Not academic: this machine is CPU-only, so the missing speedup is a live cost rather than a footnote.
  • Single socket, permanently. One CPU, no second.
  • The CPU presents 64 logical CPUs, not 32. Any core-pinning scheme that ignores SMT siblings silently fails to isolate anything. Verify with lscpu -e.
  • Uptime is coupled. Anything hosted here goes down when the box reboots. Reloading a model afterwards is cheap — about twelve seconds off the NVMe — but a host reboot takes the sites with it.
  • Local won't match frontier on the hardest work. The best US open coder lands around 60% SWE-bench. Genuinely useful, still below a lab. The win is routing volume locally and keeping a lab for the hard reasoning step — most of the cost saving, none of the pretense.

Upgrade path · priority order

What to buy next, and when

  1. A GPU — there is none in PW-1x. Six x16 slots sit empty. Directly attacks prefill and context headroom, which is the actual bottleneck. Nothing you own gets replaced. Measure CPU-only prefill first — that is the number the purchase is judged against. Used 3090s run ~$1,050 as of Sept 2026, up from $700 two years ago, the same squeeze that hit RAM. A used AMD Instinct MI50 32GB at $250–380 (Sept 2026) is the budget route: more VRAM and more bandwidth than a 3090, roughly a third of its prompt-processing speed, and drivers the community maintains rather than AMD.
  2. CPU swap — the cheap option is same-generation. A used EPYC 7532 ($140–243 as of Sept 2026) is 32 cores with 256MB L3: eight chiplets rather than the 7452's four, so twice the fabric between cores and memory. Whether that shows up as real bandwidth is a measurement — see the 4-CCD note above, where the 7452 tested in the same band as 8-CCD parts — so run the bandwidth check first and buy only if the number disappoints. Milan (7443P, 7543P, ~$950) lifts IPC and crosses the ZenDNN line, at a price that competes with a GPU rather than with the 7532.
  3. RAM to 512GB. Eight slots, 64GB modules. DDR4-3200 at 1DPC is official for Rome, but I found no vendor doc confirming 64GB dual-rank modules hold 3200 on this board — verify against the QVL before buying. Only worth it for 400B-class MoE, which this bandwidth barely supports anyway.
  4. OCuLink NVMe expansion. Two Gen4 x4 ports for fast external storage or a drive cage. Makes the missing SATA a non-event.

Done while the parts ship

gpt-oss-20b is running on the desktop under Ollama: 39 tok/s decode at 4096 context, split across card and processor because 12.1GB will not fit 8GB. That answers the hardware question and leaves the useful one open — a week of real volume work, against a written count of today’s rate-limit hits, is what tells you whether the small tier earns its place.
